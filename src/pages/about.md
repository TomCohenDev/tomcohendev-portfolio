אני מפתח Full-stack, יזם ומרצה. כבר חמש שנים אני בונה מוצרים דיגיטליים מקצה לקצה: אפליקציות לאייפון ולאנדרואיד, מערכות ווב, צד שרת, אוטומציות ומערכות AI. אני מלווה רעיון מהשיחה הראשונה ועד שהוא באוויר ובחנויות, ואז ממשיך לתחזק ולשפר אותו.

שני דברים מאפיינים את הדרך שבה אני עובד היום:

1. **אני עובד עם סוכני AI כצוות, לא ככלי השלמה.** אני מתכנן את העבודה, מחלק אותה בין סוכנים, בודק את מה שחוזר ומחליט מה עולה לאוויר. ככה מוצר שלם עובד יכול להיבנות ביום או ביומיים.
2. **כל פרויקט עולה לאוויר בצנרת אוטומטית ונקייה.** מיזוג הוא שחרור, לכל שינוי יש תצוגה מקדימה, ושום דבר לא מגיע למשתמשים בלי בדיקות.

## מוצרים שבניתי בעצמי

**[MathbookLM](https://mathbooklm.com)**: מחברת מתמטיקה שעובדת עם כתב יד. כותבים בכתב יד על קנבס אינסופי, מסמנים אזור, והמערכת מזהה את הכתב, פותרת או בודקת עם SymPy שרץ בתוך הדפדפן, וכותבת את התוצאה בחזרה על הקנבס. המודל רק מסיק ומתזמר, והחישוב עצמו תמיד דטרמיניסטי. יש בו סימולציות אינטראקטיביות שהמודל בונה, מנוי בתשלום ותוכנית פיילוט למורים.
- הטכנולוגיות: React ו־TypeScript, פורק שלי של Excalidraw, Pyodide, שרת Bun ו־Hono, Gemini עם Tool calling ו־SSE, זיהוי כתב יד (MyScript ושרת OCR שלי), Supabase ו־Lemon Squeezy.

**Gomlin Jobs**: אפליקציית חיפוש עבודה בסגנון החלקה, ב־[App Store](https://apps.apple.com/us/app/gomlin-jobs/id6744745540) וב־[Google Play](https://play.google.com/store/apps/details?id=com.gomlinjobs.gomlin). בניתי לבד את כל המערכת:
- אפליקציית Flutter.
- שרת FastAPI.
- סורקים שאוספים משרות מכ־46 מקורות ומסווגים כל משרה עם AI.
- הגשת מועמדות אוטומטית למערכות גיוס נפוצות עם Playwright.
- ממסר מיילים שמחזיר תשובות של מגייסים לתיבה האמיתית של המשתמש.
- ב־Supabase יש טבלת יכולות לכל מקור, כך שאפשר לכבות או להדליק מקור הגשה בלי לשחרר גרסה.

**Locket AI**: אפליקציית AI שעובדת על המכשיר בלבד, בלי ענן:
- צ'אט עם Gemma.
- ניתוח תמונות עם FastVLM, דרך גשר Kotlin ל־LiteRT-LM באנדרואיד ו־Swift עם MLX באייפון.
- יצירת תמונות עם stable-diffusion.cpp דרך C++ ו־FFI עם Vulkan.
- שכבת תזמור שמחליפה בין המודלים כדי לחסוך בזיכרון, כך שהאפליקציה רצה גם על מכשירים חלשים.

**nykma**: כלי מקומי שמפיק לי סרטונים ומודעות. סוכן מציע רעיון, בונה את הסרטון בקוד עם מנוע רינדור שכתבתי, ומחזיר קבצי MP4 וטקסטים לכל פלטפורמה. שום דבר לא מתפרסם בלי האישור שלי. [כתבתי עליו כאן](/blog/nykma).

**agents.tomcohen.dev**: פלטפורמת Workflows שבה סוכנים הם שלב בתהליך, משהו כמו n8n, אבל עורכים את התהליך דרך סוכן.
- כל Workflow הוא תיקייה של קבצים פשוטים.
- שלבי הקוד חינמיים, ושלבי הסוכן רצים כסשנים של T3 Code על השרת שלי, עם המודל הזול ביותר שמתאים לכל שלב.
- כל פעולה כלפי חוץ מחכה לאישור שלי באפליקציה, ויש לה מפתח אידמפוטנטיות ותקרה יומית.

## איך אני עובד עם סוכני AI

סוכן יכול לכתוב קוד טוב, אבל הערך האמיתי מגיע מהסביבה שסביבו. ה־Harness הוא הקבצים, הכלים, ההוראות וההרשאות שהסוכן עובד איתם. האורקסטרציה היא איך מחלקים את העבודה, מי בודק את מי, ומה נחשב "גמור". הרחבתי על זה [במאמר על T3 Code ו־Kitshn](/blog/t3-kitshn).

ככה נראית עבודה רגילה אצלי:

1. סוכן ראשי מקבל את המטרה ואת המגבלות.
2. הוא מאציל משימות מוגדרות לסוכני משנה, כמו מחקר, מימוש או ביקורת בלתי תלויה. כל סוכן שנוגע בקוד עובד ב־git worktree משלו.
3. הממצאים חוזרים, ומחלוקות בין סוכנים מוכרעות.
4. כל דבר נבדק מול התנהגות אמיתית: diff, הרצת בדיקות או תוצאה שאפשר לשחזר.
5. ההמתנה אוטומטית: מעקב אחרי Pull Request מעיר את הסוכן כשה־CI או ההערות מגיעים.

את הכלים לזה אני בונה ומתחזק בעצמי:
- **פורק של T3 Code.** המשך שיחה ממחשב אחר גם כשהמחשב המקורי כבוי, גיבוי של שיחות למכונה אחרת, אפליקציית אנדרואיד שמתעדכנת לבד, והכתבה קולית.
- **Helix.** סטודיו קריאייטיב עם שמונה סוכני משנה. מודלים מסוג Opus לניתוח מותג, Sonnet לקופי וסצנות ו־Haiku לתיקון סכמות. יש בו שער הוצאות, תיעוד מקור לכל נכס, ורנדרר מבודד בלי רשת ובלי סודות.
- **nykma, שבא אחרי Helix.** מדדתי ש"סוכן אחד, פרומפט קצר וארגז חלקים לשימוש חוזר" מנצח צנרת של שמונה סוכנים, ותיעדתי למה. יש בו הערכות לפרומפטים: 14 בריפים קבועים, גרסאות פרומפט קפואות והשוואה עיוורת של עלות ואיכות.
- **סוכנים בתוך מוצרים.** מערכת שבונה אתר דמו לעסק, מצלמת אותו בארבעה מכשירים ומתקנת את הבעיות. סוכנים שכותבים ומפרסמים כל בוקר גיליון חדשות ובודקים את הדף החי. סוכן שיווק שמכין מודעות לאישור.
- **שרתי MCP** שנותנים לסוכנים גישה מובנית לנתונים: [מאגר חולשות אבטחה](https://github.com/TomCohenDev/vulnerability-registry-mcp) ונתוני השימוש של Gomlin.

**כמה זמן זה חוסך? לפי ה־commits:**
- מערכת לידים שלמה עם דשבורד נבנתה ביום אחד.
- פלטפורמת ה־Workflows נבנתה ביום אחד.
- אתר הוראה עם מבחנים וחיבורים ל־Google Classroom נבנה ביום אחד.
- שירות סריקה עם API, דשבורד וגיבויים, שהחליף תהליך n8n ישן, נבנה ביומיים.
- Helix: 342 commits ב־12 ימים.

**הכללים שלי:**
- כל דבר שיוצא החוצה (פוסט, מייל, פרסום, הוצאה כספית) מחכה לאישור אדם.
- מפתחות לא נמצאים בהישג יד של הסוכן.
- טקסט חיצוני הוא מידע ולא הוראות.
- לכל פעולה יש תקרה.
- שום דבר לא נחשב "גמור" לפני שנבדק.

## CI/CD: כל מיזוג הוא שחרור

את צנרת השחרור של כל מה שאני בונה אני מתכנן בעצמי. המטרה תמיד זהה: אף אחד לא מריץ דיפלוי ביד, כל שינוי אפשר לראות לפני שהוא עולה, ושינוי שבור לא מגיע בשקט למשתמשים.

### אפליקציות מובייל
- **Gomlin עם Codemagic.**
  - ענף staging עולה ל־TestFlight ול־Google Play Internal, וענף main עולה לחנויות.
  - מספרי build מתעדכנים לבד, והחתימה מגיעה מסודות ב־CI.
  - יש flavors נפרדים ל־dev, staging ו־prod, ובניות חנות עם obfuscation.
- **tick3d לאייפון עם GitHub Actions.**
  - ה־CI מייצר את פרויקט ה־Xcode, בונה, חותם עם מפתח App Store Connect ומעלה ל־TestFlight.
  - כל build עובר אוטומטית לבודקים חיצוניים דרך ה־API של App Store Connect. הסקריפט אידמפוטנטי, כך שהרצה חוזרת לא שולחת פעמיים.
  - כל Pull Request בודק גם את צנרת ה־iOS עצמה, כדי ששבר יתגלה בביקורת ולא ביום השחרור.
- **הפורק של T3 Code.** APK חתום לאנדרואיד נבנה ב־CI ומתעדכן לבד, ויש בניות לילה למחשב.

### אתרים
- **Cloudflare Workers ו־Pages** לכמעט כל האתרים שלי:
  - כל push ל־main עולה לאוויר.
  - לכל Pull Request יש קישור תצוגה מקדימה.
- **בדיקה אחרי דיפלוי.**
  - ב־MathbookLM הצנרת מחכה עד שהאתר החי מחזיר את ה־commit החדש ב־`/version.json`. "עלה" אומר שהמשתמשים באמת רואים אותו.
  - באתר הזה כל שינוי עובר lint, בדיקת טיפוסים, build ובדיקת אתר, ואחרי כל דיפלוי workflow נפרד בודק את האתר החי.
- **Firebase Hosting** עם ערוץ תצוגה מקדימה לכל Pull Request.
- **OpenNext על Workers** לאתרי Next.js עם Sanity CMS.

### שרתים ו־VPS
- **GHCR ו־SSH.**
  - בכל push רצות הבדיקות ונבנית תמונת Docker שעולה ל־GHCR.
  - השרת מושך אותה ועולה מחדש עם Docker Compose.
  - מפתח ה־SSH של השרת מקובע, ו־staging ו־production רצים בנפרד מאחורי nginx.
- **Kitshn על השרת שלי.**
  - הדיפלוי מתבצע מ־GitHub Actions עם OIDC, בלי מפתחות דיפלוי שמורים.
  - Docker רץ בלי root, ובדיקות בריאות מוודאות שתנועה מגיעה רק לאפליקציה תקינה.
  - הדיפלוי הראשון של כל ריפו דורש את האישור שלי.
  - יש גיבוי יומי של הנתונים, וכל אפליקציה פרטית יושבת מאחורי Cloudflare Access.
- **הפעלה מחדש בטוחה.** סקריפט דיפלוי שמסרב להפעיל מחדש באמצע עבודה רצה, ועבודות שנקטעו ממשיכות כשהשרת עולה.
- **סריקות אבטחה ב־CI:** Dependabot, pip-audit, Trivy ו־OSV.

### פורק שמתחזק את עצמו
- ב־T3 Code, workflow מתוזמן ממזג את המקור כל שלוש שעות.
- כשהמיזוג מתנגש או שהבדיקות נכשלות, נפתח issue ונקרא סוכן תיקון שרץ על השרת שלי.
- הסוכן פותח Pull Request עם התיקון וממזג אותו רק כשה־CI עובר.

### Kitshn
[Kitshn](https://github.com/Yarden-zamir/kitshn) הוא הפרויקט של ירדן זמיר: פריסת אפליקציות מ־GitHub ל־Cloudflare ולמכונות שלך, עם מפה שקובעת מי יכול לפתוח כל אפליקציה.
- אני מריץ מופע משלו ופורס דרכו את האפליקציות שלי.
- תרמתי בפורק שלי, [TomCohenDev/kitshn](https://github.com/TomCohenDev/kitshn), כ־28 commits:
  - ממשק המפה: מראה שטוח, מצב בהיר וכהה, ומפת דמו של חברה קטנה.
  - האתר kitshn.com: עמוד הבית, enterprise, How it works ו־install.
  - סרטון הסבר עם Remotion ו־ElevenLabs.
- אני משתמש בו כל יום יחד עם סוכנים: הסוכן מציע שינוי במפה, אני מאשר, והוא פורס.

### tick3d
[tick3d](https://github.com/Yarden-zamir/tick3d) הוא איקס־עיגול תלת־ממדי של ירדן זמיר, על קובייה של 4×4×4.
- ממשק נאו־ברוטליסטי עם 12 ערכות נושא.
- סיבוב של המגדל בגרירה.
- צ'אט בזמן אמת בין שחקנים.
- אפליקציית iOS ב־Capacitor שנבנית ועולה ל־TestFlight מה־CI, עם הפצה אוטומטית לבודקים.
- "tick3d Factory" (בפיתוח): סורק את הריפו ומציג אותו כמפעל תלת־ממדי מונפש. ה־imports הם מסועים, קריאות HTTP הן צינורות ודיפלוי הוא רכבת.
